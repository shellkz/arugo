# 回合制 Roguelike 遊戲
https://github.com/shellkz/arugo

## 遊戲介紹
玩家要在隨機生成的地下城探索，其中有敵人遊蕩，踩到傳送門即可進入下一層，目標是盡可能往深處探索。

### 遊戲規則

- **玩家回合**：玩家執行移動，若敵人在攻擊範圍內則自動攻擊
- **敵人回合**：玩家行動結算後，所有存活的敵人依序行動；若玩家在其攻擊範圍內自動攻擊
- **傳送門**：每層地圖皆有傳送門，踩到會進入下一層
- **擊殺獎勵**：擊殺敵人會追加一次行動機會

### 操作方式
| 按鍵 | 行為 |
|------|------|
| `W` `A` `S` `D` | 四方向移動；移動後自動攻擊範圍內敵人 |
| `Z` | 跳過本回合行動（等待）|

## 執行方式

直接執行 `dist/Arugo.exe`，不需安裝任何軟體或相依套件。

## 技術棧
- C++17
- SFML 3.0(一種視窗程式框架，處理多媒體繪製、輸入事件)

## 系統

### 戰鬥系統
**核心**：

`GameWorld.cpp`、`ActionQueue.cpp`、`BattleCommand.cpp`

**概要**：

遊戲為回合制，玩家移動後自動攻擊鄰近敵人，敵人亦然。擊殺敵人會追加一次行動機會，可策略性一次擊殺所有敵人。

**實作概念**：

戰鬥依序經過四個階段：`DecideActor → DecideCommand → ExecuteCommand → PresentCommand`，結束後循環回 `DecideActor`。

其中`DecideCommand` 需要等待玩家按鍵，`PresentCommand` 需要等待視覺效果計時結束。

但遊戲的主迴圈同時處理輸入、更新、繪製，不會在任何地方阻塞等待。這意味著「等待玩家輸入」或「等視覺效果播完」都不能用 `while(!input)` 的方式實作，否則整個畫面會卡死。

解決方式是以 `TurnState` 狀態機維護目前回合的進度，每幀進入 `update()` 時只執行當前狀態對應的邏輯——若條件未滿足（輸入尚未到來、計時未到）則直接 return，留到下一幀再檢查，不阻塞主迴圈。

因此在這種「遊戲引擎主迴圈處理所有事情」的架構中，導入狀態機處理非同步戰鬥有其必要性。

行動順序由 `ActionQueue`（內部為 `std::deque<Entity*>`）決定：每回合從隊首取出當前行動者，行動結束後再重新排回隊尾。觸發擊殺獎勵時，玩家透過 `enqFront()` 插隊到隊首，即可立即獲得下一回合，清晰呈現「插隊」語意。

每個 Entity 的行動皆封裝為 `BattleCommand` 的子類別（`MoveCommand`、`WaitCommand`），統一以 `execute(Entity& actor, GameWorld& context)` 介面呼叫。新增行動種類只需新增一個子類別，不觸動狀態機或佇列的任何邏輯。

### TileMap系統
**核心**：

`TileMap.cpp`

**概要**：

地圖由固定大小的格子（Tile）組成，每格可為地板、牆壁、傳送門、虛空，每層樓皆隨機生成。

**實作概念**：

分四步生成每一層地圖。
1. 首先將整張地圖填滿 Void（虛空）
2. 接著在中央區域刻出矩形地板（Top）
3. 再執行有機邊緣處理：對邊緣格子依據距中心的距離調整機率隨機移除，使地圖輪廓不規則，避免永遠方正。
4. 最後進行前緣偵測：掃描所有地板格，若其正下方不是地板，即從該位置向下生長一根三格高的牆柱（WallTop → WallMiddle → WallBottom），賦予地圖俯視 2.5D 的立體厚度感。

### 資源管理系統（ResourceManager）
**核心**：

`ResourceManager.cpp`

**概要**：

統一管理字型、貼圖等資源，透過可辨識名稱索引，不用自己記檔案路徑。

**實作概念**：

`ResourceManager` 透過`std::unordered_map<std::string, T>` 集中持有 `sf::Font` 與 `sf::Texture`，避免同一資源重複讀取。各子系統透過參考取用，生命週期由 `ResourceManager` 統一管理，消除資源洩漏風險。

## 問題與解決

### 編譯後移到其他電腦執行，缺少 DLL

**原因**：以 Debug 模式編譯時，產生的 `.exe` 相依開發者工具的執行期 DLL，其他電腦若未安裝相同開發環境就無法執行。

**解決**：改用 Release 模式編譯，並在 CMakeLists.txt 中加入打包指令，將所有必要的 DLL（SFML 與 C++ runtime）打包到exe檔案。可在任何 Windows 電腦上直接執行，不需任何外部依賴。
